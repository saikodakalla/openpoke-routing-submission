# Chat interface

Operate mode. Unbranded, neutral white conversation canvas with charcoal text and
muted gray controls. A single centered column, maximum 760px, is the primary surface.
A compact New chat action sits above; there is no marketing header or footer.

Empty state: one simple question and the composer. With messages, user requests appear
in soft gray bubbles at the right; assistant responses are plain readable text at the
left. Real operation activity sits between the user message and the assistant answer,
with expandable steps. Do not animate invented intermediate work or private reasoning.

The multiline composer stays within the viewport bottom, using a restrained border,
rounded corners and an icon Send button. Enter sends; Shift+Enter inserts a newline.
A quiet offline/live label communicates actual mode. Controls have visible keyboard
focus; mobile honors safe areas and avoids horizontal overflow. Respect reduced motion.

Technical evidence opens inline only when requested. Vector exploration is lazy and
attached to a request that used vector search. No total task/vector counter appears.
Draft approvals live beside the relevant reply. New work is normally inferred from a
clear action and resolved recipient; a subject question may offer “This is something new”.
There is no global new-work checkbox or hidden sample metadata.

The top System view control opens an optional architecture pane for the selected
request. Desktop splits the canvas; narrow screens switch to full-width inspection
with a close action returning to chat. Mobile uses a readable vertical layer flow.
The diagram follows the supplied ownership → vector fallback → verification →
execution/clarification architecture. Layer colors derive only from persisted events;
blocked, failed, running and bypassed outcomes remain distinct. A request selector
preserves earlier traces; sending a new prompt selects it automatically. Actual vector
retrieval reveals a local PCA projection with a cached query marker, retrieved-task
connections, original cosine values, verification evidence and task → agent mapping.
Opening inspection never triggers a paid embedding call.

User-facing questions never demand task IDs, thread IDs or internal schema fields.
Saved names and natural plan/calendar references resolve internally. Ask one concrete
real-world distinction only when records cannot resolve it. The inspector uses filled
arrowheads, explicit decision diamonds and independent direct/verified/uncertain lanes.
Arrow endpoints meet the specific destination without crossing captions or group fills.
The offline label explicitly states its limited language understanding.

Database/schema/vector inspection uses the existing optional system pane. Native table
selection, horizontally scrollable records, explicit pagination and underlined foreign
key links support technical inspection without widening the page on mobile. No SQL
console is exposed. The diagram's SQLite and Chroma cylinders are keyboard-operable
buttons; matching text controls remain available on mobile. Candidate verification
shows the actual four checks, scores and winning margin. Synthetic order approval is
beside the prepared basket. A running cold semantic build lights the embedding stage.
